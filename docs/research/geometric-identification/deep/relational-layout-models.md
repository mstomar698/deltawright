# Relational layout models: X-PERT alignment graph, ReDeCheck RLG, GWALI layout graph, Galen specs

**Status: FINAL (v3).** Four papers read in full text, Galen spec guide read in full, and the shipped source of X-PERT (orso-research-lab/xpert) and ReDeCheck (redecheck/redecheck) read for the relation-computation code. Every number below is traceable to those texts; items marked UNVERIFIED were not checked against a primary text.

## 1. What it does

**X-PERT (Roy Choudhary, Prasad, Orso, ICSE 2013).** Cross-browser-incompatibility (XBI) detector whose novel component is *relative-layout comparison*: each rendered page becomes an **Alignment Graph** — nodes are visible DOM elements (rectangles), edges are geometric parent/child (containment) and sibling relations, each qualified by positional attributes. The graphs from two browsers are compared edge-by-edge over DOM-matched nodes; a mismatch in edge type or attribute set is one structure XBI reported on the element's neighbourhood. Motivated by a 100-site manual study (23 sites with XBIs; structure XBIs in 13/23 = 57%) in which the authors recognised structure XBIs "through a difference in the relative position of an element with respect to its immediate neighbors, rather than a difference of its absolute size or position".

**ReDeCheck / Responsive Layout Graph (Walsh, McMinn, Kapfhammer; ASE 2015 → ISSTA 2017 → STVR 2020).** Lifts the alignment graph across viewport width: the page is rendered at sampled widths (320 or 400 → 1400 px), an alignment graph is extracted at each, and per-edge *alignment constraints* (width range, relation type, attribute set) plus per-node *visibility constraints* are stitched together, with binary search finding the exact width at which anything changes. STVR 2020 (ReDeCheck-RM) diffs the RLGs of two page versions to flag regressions; ISSTA 2017 checks one RLG for internal inconsistencies (element collision, element/viewport protrusion, small-range layouts, wrapping) with no oracle.

**GWALI (Alameer, Mahajan, Halfond, ICST 2016).** Detects internationalization presentation failures (translated text expanding/contracting) by building a **Layout Graph** — a *complete* graph over visible HTML elements *and their text runs*, every pair labelled with direction/alignment/containment relations computed from bounding rectangles — for a baseline-locale page and the page under test, matching nodes across locales, comparing only k-NN spatial *neighbourhoods*, filtering with two heuristics (ignore text-vs-text alignment changes; ignore direction changes whose centre-to-centre angle moved < α = 45°), and ranking suspicious elements. The companion ICSME 2016 study ran it on 1,020 baseline/translated pairs.

**Galen Framework specs (galenframework.com, spec language 2.x).** A declarative layout-assertion DSL over *named objects that are still located by id/css/xpath*; the geometry is only in the assertions: `near`, `above`/`below`, `left-of`/`right-of`, `inside [partly]` with per-side margins, `aligned horizontally|vertically all|top|bottom|left|right|centered [error px]`, `centered horizontally|vertically|all inside|on [error px]`, `on <corner> edge`, `contains [partly]`, `width`/`height` ranges (px, %, `~`, `x to y`, `% of obj/width`), `count`, `visible`/`absent`, plus text/css/colour-scheme/image (pixel diff with `error Npx|N%`, default colour `tolerance 30`, `analyze-offset`, blur/denoise filters) and OCR via Google Vision. No accuracy study exists (documentation only).

## 2. Exact representation

**Coordinate frame (all).** Axis-aligned bounding boxes in CSS px from the DOM API, top-left (x1,y1) / bottom-right (x2,y2). ReDeCheck's injected JS returns `getBoundingClientRect()` left/top/right/bottom (no scroll offset added — the page is captured unscrolled in a tall window) and the Java side reads them with `getInt`, i.e. fractional px are truncated; elements under 5×5 px, and anything with opacity 0 / visibility hidden|collapse / display none, are dropped, and body is stretched to the max y2 of any element. X-PERT drops boxes with any dimension ≤ 5 px, negative coordinates, and empty DD/DIV/DT/P/TD/TR containers. GWALI computes MBRs for elements *and* text runs by executing JS in Firefox and runs at a fixed 1920×1080.

**X-PERT Alignment Graph** A = (E, R, T, Q, F). *Contains*: e1 ≺ e2 iff x1¹ ≤ x1² ∧ y1¹ ≤ y1² ∧ x2¹ ≥ x2² ∧ y2¹ ≥ y2² (non-strict, so equal boxes contain each other), tie-broken by XPath prefix; *parent* = smallest-area container (the code sorts by area ascending, then XPath length descending, and scans for the first container). T = {parent, sibling}; Q as stated in the paper: child left/right/centre-justified and top/bottom/centre-justified within its parent; sibling above/below/leftOf/rightOf plus top/bottom/left/right edge alignment. The paper says attributes "can be simply computed by comparing the x and y coordinates" and gives **no tolerance; the shipped code does**: sibling edge-aligned iff |edge1 − edge2| ≤ 5 px (`deltaW = deltaH = 5`); leftRight iff a.x2 ≤ b.x1 and topBottom iff a.y2 ≤ b.y1 (exact); parent-child *fill* iff centre, left and right edges all within 5 px; otherwise centred iff |centre diff| ≤ cw/3, else left-justified iff |x1 diff| ≤ cw/3, else right-justified iff |x2 diff| ≤ cw/3 (tolerance = one third of the *child's* width/height, mutually exclusive in that priority); justification is only computed when 0.1 < child/parent size ratio < 0.7, and children under 15 px inside parents under 15 px are ignored. Each justification carries an error ratio |a − b|/δ used at diff time. Ignored tags include A, SPAN, LABEL, FORM, UL, STRONG, EM, TR, TBODY, OPTION, IFRAME, CANVAS.

**ReDeCheck RLG** = (E, R, F_VC, F_AC). Nodes = presentational elements identified by absolute XPath; hierarchy is *geometric*: e2 is contained in e1 iff its rectangle lies inside e1's (R-tree `contains` query, ties where XPaths nest resolved by DOM ancestry), parent = innermost container, siblings share a parent; edge (e1,e2) ∈ R iff at some width they are parent-child or siblings. **Alignment constraint** (x1, x2, t, P): inclusive width range, t ∈ {pc, s}, P ⊆ Q. **Attribute alphabet Q (paper):** parent-child LJ/RJ/CJ and TJ/BJ/MJ; sibling *positioning* L, R, A, B; sibling *alignment* TE/BE (allowed with L/R) and LE/RE (allowed with A/B); O = overlap (ISSTA 2017). **Code (shef.layout, master):** sibling edges also carry xMidAlign/yMidAlign; edge/mid alignment iff within **3 px**; `leftOf` iff mid-x(n1) ≤ x1(n2) ∧ x2(n1) < x2(n2); `rightOf` iff x2(n2) ≤ mid-x(n1) ∧ x1(n1) > x1(n2); `above` iff y2(n1) ≤ mid-y(n2); `below` iff y2(n2) ≤ mid-y(n1) (so "above" means n1's bottom clears n2's vertical midpoint, not n2's top; the STVR text's "div[1]'s y2 value is greater than div[2]'s y1" is a typo); `overlapping` iff the intersection rectangle has width > 1 and height > 1; parent-child hFill/vFill within 5 px, else centred/left/right (top/middle/bottom) within 3 px in that priority. **Visibility constraint** (vmin, vmax): widths where the element is present with visibility true and opacity > 0. Invariants: at any width ≤ 1 visibility constraint per node and ≤ 1 alignment constraint per edge. The ASE 2015 RLG additionally had *width constraints* (element width as a linear function of viewport width; `WidthConstraint.java` still exists); the rRLG and the STVR RLG drop them.

**GWALI Layout Graph** LG = ⟨V, F⟩, complete graph. Node ⟨t, c1, c2, x⟩, t ∈ {Element, Text}; text nodes get XPath + "/text()" and the rendered text's MBR; inline tags embedded in text are merged into one Text node. **R** = direction {North, South, East, West} ∪ alignment {Top, Bottom, Left, Right}-Aligned ∪ containment {Contains, Intersects}, quoted computation: "if v.y2 ≤ w.y1 then … North … if v.y2 = w.y2 then … Bottom-Aligned … if (v.x1 ≤ w.x1) ∧ (v.y1 ≤ w.y1) ∧ (v.x2 ≥ w.x2) ∧ (v.y2 ≥ w.y2) then … Contains" — exact equality, no tolerance. Excluded nodes: hidden elements (display:none, visibility:hidden, zero width/height, clip to 0 px, huge text-indent + overflow:hidden), borderless containers whose background matches the parent's, very small tags, styling-only tags (<font>, <strong>, <b>), unselected <option>.

**Galen.** Objects are boxes with `.left() .right() .top() .bottom() .width() .height()` in page px (`screen` = whole page, `viewport` = client window); `@(dx, dy, dw, dh)` corrections adjust a box; ranges are exact, `a to b`, `<`, `>`, `<=`, `>=`, `~` (approximate), `N %` / `N % of object/width`; alignment and centring accept an explicit error in px (e.g. `aligned horizontally all menu_item-2 1px`, `centered horizontally inside box 10px`). Every spec first requires all referenced objects to be visible.

## 3. Algorithm

**X-PERT.** (1) Crawl both browsers with Crawljax; diff state graphs (labelled-transition isomorphism from CrossT) → behaviour XBIs + matched page pairs. (2) `matchDOMs` with the WebDiff/CrossCheck *match index* — weighted XPath + attributes + descendant hash, in [0,1]. (3) Build the alignment graph: filter, sort by (area, XPath), scan for the smallest container — O(n²) worst case — then sibling edges within each parent's child list (O(k²) per parent) and attributes per edge. (4) Diff per matched node: parent identity, then justification flags (XOR, but only if both sides have a significant size difference and the holding side's error ratio < 0.8), then sibling edge-alignment flags (XOR) and direction flags (XOR **and** the inter-box gap differs by > 5 px between browsers — `diffThreshold = 5`). Runtime: "the whole analysis, including crawling, terminated in less than an hour" per subject (Win7, 4 GB; pages of 817–140,611 DOM nodes).

**ReDeCheck extraction (STVR 2020 Alg. 1–3; code `RLGExtractor`, `ResponsiveLayoutGraph`).** `GETSAMPLEWIDTHS`: S = {wmin, wmin+step, …, wmax} ∪ (breakpoint mode) {b, b−1 for min-width, b, b+1 for max-width} for every `(min|max)-width: N(px|em)` media expression in all referenced CSS (em × 16). Worked example: max-width:768px, step 60, 400–1400 → {400, 460, …, 760, 768, 769, 820, …, 1340, 1400}. Render at each width (Selenium; ISSTA 2017 Firefox, STVR 2020 PhantomJS 2.1.1 via a 320-px pop-up window), inject JS to dump per-element XPath, box, visibility, overflow; build an alignment graph per width (R-tree containment → parent map → sibling pairs). Walk widths ascending; when a node appears/disappears or an edge's key (XPath pair + attribute string) changes, **binary search** between the two sample widths (`searchForLayoutChange`: render at mid, test key presence, recurse until max − min = 1) and split the constraint at w_change−1 / w_change. Sampling modes: EXHAUSTIVE (step 1 → 1001 renders over 400–1400), INTERVAL, INTERVAL-BREAKPOINTS.

**RLG differencing (Alg. 4).** Nodes matched by *identical absolute XPath*; symmetric differences of node sets, visibility-constraint sets and edge sets are reported; per edge, an unmatched constraint is a *bounds difference* (same t,P, different range → report the width symmetric difference), an *attributes difference* (same range, different t/P) or *compound*.

**ISSTA 2017 detectors over one rRLG.** Alg. 1: for a sibling constraint containing O, look at the constraint at amax+1; no O there → *element collision*; else if one element is the other's ancestor at amax+1 → *element protrusion*. Alg. 2: a visible non-body node with no parent-child constraint over some width range → *viewport protrusion*. Alg. 3: constraint with amax − amin ≤ thres (**thres = 5 px**; code tests `< 5`) whose neighbours on both sides exist with different attributes → *small-range layout*. Alg. 4: rows = sibling constraints with L or R and neither A nor B; an element in a row of ≥ 2 that leaves the row at the adjacent narrower range → *wrapping*.

**GWALI.** Build both LGs (complete graph, O(|V|²) edges; "building graphs" = 0.19% of runtime). Match nodes with an adapted WebDiff matcher (attributes, tag names, Levenshtein on XPaths — needed because Google Translate inserts wrapper tags; "close to perfect" here). Neighbourhood of n = union of k-NN (JSI R-tree; distance from each of n's 4 corners + centre to the nearest point of another MBR), k ∝ |V|. For every neighbourhood edge compute δ = F(e) △ F(e′). Filters: drop alignment relations from δ when an endpoint is Text; drop direction relations when the centre-to-centre angle changed by < 45°; when a direction relation changed, add the LCA's text-children selector. Score = (#appearances in I) + Σ|δ|; sort. Runtime avg 9.75 s (min 6.08, max 36.21): browser start 36.08%, MBR collection 60.06%, graph build 0.19%, compare 3.65%, filter 0.01%.

## 4. Act step and verification

Nothing in this cluster *acts* on an element. X-PERT reports XPath + screen coordinates highlighted on side-by-side screenshots; ReDeCheck reports {XPaths, width range} (e.g. "BODY/NAV/UL/LI[1] sibling of BODY/NAV/UL/LI[5] {A} between 768 -> 811") and the developer re-renders at a width in the range — ISSTA 2017 measured that cost: **137 distinct viewport ranges for 33 distinct failures ⇒ ≤ 4.2 visual checks per real failure**; GWALI returns a ranked XPath list (median rank 3, > 81% in the top 6). Galen's only act is Selenium locating the named objects; the geometric predicates are assertions with px error budgets. Correctness/observability is checked manually everywhere (ISSTA 2017 adds a "non-observable issue" class for coordinate-level collisions with no visible effect; VISER 2019 later automated that check by opacity toggling — not read here).

## 6. Invariances shown / NOT shown

- **Shown — relative relations are invariant across rendering engines where absolute geometry is not** (X-PERT): 31 FPs vs CrossCheck+'s 389 on the same 14 sites; 1 duplicate vs 52. The 5-px edge tolerance, cw/3 justification tolerance, 0.1–0.7 size-ratio gate and 5-px gap-change threshold are what make that precision 76% rather than the paper's naive equality.
- **Shown — relation sets are piecewise-constant in viewport width** (ReDeCheck-RM): a pair's label holds over ranges of tens–hundreds of px, so 60–80 px sampling + binary search matches 1-px exhaustive sampling except one change, at < 30 s vs 108 s; changes cluster "between the regular breakpoints … well away from the default widths suggested by most testing tools".
- **Shown — tolerant to sub-observable jitter in one direction only**: 3 of ReDeCheck-RM's 4 misses were DOM changes "too small to produce a difference in the extracted attribute sets"; the single FP was the mirror (DOM differed enough to change the RLG with no visible change).
- **Shown — neighbourhood scoping + 45° angular tolerance makes relations invariant to translation-driven reflow** (GWALI 91% vs X-PERT 55% precision on identical pages); text-vs-text alignment changes are deliberately ignored.
- **NOT shown:** dynamic/JS pages (ISSTA 2017 future work; GWALI disabled JS after load; X-PERT compares static snapshots), z-index layering (explicit GWALI FP cause), RTL locales (GWALI limitation), multiple viewports for GWALI (one fixed size), fractional/sub-pixel layout (ReDeCheck truncates to int; nobody discusses DPR), scrolling/fixed-position elements, cross-browser stability of the *geometric parent* itself, and stability across app versions beyond XPath identity.

## 7. Failure modes

- **X-PERT:** 23 of 31 FPs are structure FPs — SaiBaba 9 FP/4 TP, DivineLife 6, DesignTrust 3 — with no per-cause analysis; 6 image FPs on Konqueror; the one miss is BMVBS (mobile site). GWALI's re-run shows the systemic cause: X-PERT's structure module "detected any difference with the oracle as a failure" (55% precision when text reflows legitimately).
- **ReDeCheck small-range = the 1-px-flip problem:** 43 of 195 small-range reports (22%) were FPs from "coincidental alignment attributes … an element might not have any particular horizontal alignment within its parent, yet for a small-range appear to be center justified, due to chance co-ordinate values … for a one-off or small series of viewport widths" — even with the 3-px tolerance in the code. 147 TP small-range reports on Accountkiller collapsed to **one** failure (an icon grid where every pair is a sibling edge).
- **Wrapping FPs:** 5 of 15 — three elements "misclassified as a 'row'".
- **NOIs (83 reports):** collisions of boxes padded by invisible CSS padding and protrusions clipped by overflow:hidden — box geometry ≠ painted geometry.
- **ReDeCheck-RM misses:** an inline <a> excluded from the RLG carried a visible regression; INTERVAL without breakpoints loses 1–2 changes on Ashton Snook and Pay Demand at every step because they change exactly at CSS breakpoints; Treehouse has so many breakpoints that IB samples *more* widths than I.
- **GWALI FPs (≈ 9%):** z-index sliders flattened into one plane; direction changes > 45° when a large text block shrinks.
- **Ground-truth noise:** 3 authors disagreed on 21/60 mutants; ReDeCheck reports were classified by one author and reviewed by another.

## 8. What to borrow for a DOM-first geometric web locator

1. **Encode targets relatively, by neighbourhood.** X-PERT's core result: relations to parent + siblings survive engine changes; absolute coordinates do not (389 vs 31 FPs). Playwright: one `CDPSession.send('DOMSnapshot.captureSnapshot', {computedStyles:['display','visibility','opacity','overflow','z-index'], includePaintOrder:true})` yields every node's layout `bounds`, text runs and paint order in one round-trip — the same data ReDeCheck and GWALI collected with injected JS; add `window.scrollX/Y` (or use `document.documentElement` bounds) to move into page coordinates.
2. **Geometric parent = innermost containing box, not DOM parent.** Both X-PERT (area-sorted scan) and ReDeCheck (R-tree `contains`) use it; it is immune to wrapper-div churn. Implement with area sort + scan (fine for the 106–1,469-element pages studied) or an R-tree; tie-break equal boxes by DOM ancestry as X-PERT does.
3. **Keep the proven alphabet and the *code's* tolerances, not the papers' equalities:** edge alignment ±3–5 px; centre alignment ±3 px; justification tolerance scaled to child size (X-PERT: cw/3) and only for children 10–70% of the parent; fill = all three edges within 5 px; direction via midpoint tests (`above` iff y2(a) ≤ mid-y(b)); overlap only if the intersection exceeds 1×1 px; report a direction flip only if the gap changed by > 5 px; treat a justification flag as reliable only if its error ratio < 0.8. GWALI adds the continuous alternative: centre-to-centre angle with a 45° band.
4. **Text runs as first-class anchors** (GWALI): index text-node MBRs (`DOMSnapshot` `textBoxes`, or `Range.getClientRects()`), so "the input right of the label 'Email'" is a relation between a text box and an element box; suppress alignment relations between two text nodes.
5. **Neighbourhood matching, not graph isomorphism:** score candidates by |F(e) △ F(e′)| over k-NN neighbourhoods (k ∝ |V|, 5 probe points per box); GWALI's median rank 3 came from exactly this plus LCA expansion for pushed rows.
6. **Width-indexed relations:** if a locator must survive breakpoints, record (t,P) per width range using 60–80 px steps + CSS-breakpoint widths (b−1, b) + binary search with `page.setViewportSize`; parse `min-width`/`max-width` from `document.styleSheets` (em × 16 as ReDeCheck does).
7. **Filter like the tools do:** drop < 5×5 px boxes, opacity 0, visibility hidden/collapse, display none; but *do not* drop <a>/<label>/<span> wholesale — that cost ReDeCheck a real regression and would cost a locator its most common click targets. Use `elementFromPoint`/`DOM.getNodeForLocation` on the box centre to confirm the target is actually hit-testable (paint order from the snapshot approximates z-index, which GWALI lacked).
8. **Verification vocabulary from Galen:** express post-action assertions as Galen-style predicates with explicit px/percent error budgets (`inside container 10px top left`, `aligned horizontally all X 1px`, `width 95 to 100 % of main/width`) rather than crisp booleans.
9. **Avoid:** exact-equality alignment (ReDeCheck's 22% small-range FPs); complete-graph comparison at page scale (147 reports for one grid fault; GWALI needed neighbourhoods); single-viewport checks (spotchecking missed 19–34% of RLFs and 44% of subtle regressions); box geometry without paint/overflow awareness (83 NOIs; z-index FPs); XPath as the only node identity across versions (ReDeCheck-RM) — pair it with attribute similarity (X-PERT/GWALI match index).

## 9. Open questions this cluster leaves

- No paper measures how many relation attributes flip under ±1 px jitter, zoom, DPR or font changes; the tolerances (3, 5, cw/3, 45°) are unexplained constants and the papers do not even state them.
- No paper re-finds an element from a relational description; all three compare a whole graph against a reference graph. Precision of relation-based *identification* (one target among similar siblings) is unmeasured.
- Geometric-parent stability across browsers/versions and the cost of R-tree vs O(n²) parent finding are not reported.
- XPath-identity node matching (ReDeCheck) vs probabilistic matching (X-PERT/GWALI match index) is never compared on the same data.
- Whether relation sets can be predicted at an unseen width from the sampled ranges (interpolating an RLG) is untested; the ASE 2015 width constraints were dropped rather than evaluated (UNVERIFIED: the ASE 2015 text was not on disk).
- Galen's predicate semantics at edges (`near … Npx left` = gap between facing edges within range — inferred from the examples, UNVERIFIED against source) have no published false-positive data.
